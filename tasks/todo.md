# FlowLens task checklist

The detailed acceptance and verification steps for the active phase live under `docs/superpowers/plans/`. This checklist is the compact cross-phase status ledger.

## Phase 0: Reconnaissance

- [x] Read repository instructions and both copies of the master brief.
- [x] Inventory files, Git history/remote, runtime, and absence of baseline commands.
- [x] Verify initial stack choices against current primary documentation and registry compatibility.
- [x] Record risks, design specification, ADRs, and requirement matrix.
- [x] Complete the bounded adversarial architecture review and record rulings.
- [x] Commit and push Phase 0 artifacts.

## Phase 1: Canonical foundation

- [ ] Install and lock the strict TypeScript application/test toolchain.
- [ ] Implement validated IDs, SI units, coordinates, entities, claims, and projects.
- [ ] Implement idempotent authoritative commands, inverse history, causal revisions, lease fencing, and constraints.
- [ ] Implement canonical serialization, versioned seeded randomness, immutable run snapshots, and stale-result rules.
- [ ] Implement claim resolution, confidence propagation, source integrity, invalidation, central admissibility, backend, recommendation, and experiment contracts.
- [ ] Implement repository contracts, staged IndexedDB writes, migrations/recovery, fenced leases, hardened export/import, and tombstoned deletion.
- [ ] Implement scoped validated job/ingestion worker protocols with cancellation, type-specific resource limits, and cleanup.

## Phase 2: Shell and design system

- [ ] Implement routes, onboarding, project lifecycle, workspace panels, and sample project.
- [ ] Implement tokens, accessible primitives, focus/error/status patterns, and responsive layout.
- [ ] Verify create/open/save/reopen at desktop and narrow viewport sizes.

## Phase 3: Interactive room editor

- [ ] Implement domain-to-R3F projection, cameras, controls, selection, and WebGL fallback.
- [ ] Implement entity manipulation, snapping, constraints, layers, duplicate/delete, and undo/redo.
- [ ] Implement synchronized keyboard/form/table editing and critical visualization alternatives.
- [ ] Verify projection/serialization tolerance, resource disposal, and adaptive quality.

## Phase 4: Creation and correction

- [ ] Implement manual dimension-first room creation and correction.
- [ ] Implement safe project/mesh import and review.
- [ ] Implement camera/XR capability, permission, denial, and fallback states.

## Phase 5: Evidence ingestion

- [ ] Implement note, measurement, equipment, sensor, photo, and video ingestion.
- [ ] Implement content validation, metadata stripping, quota/retention, provenance, and conflicts.
- [ ] Complete portable export/import and verified deletion.

## Phase 6: Tracer analysis

- [ ] Generate deterministic video and motion-field fixtures.
- [ ] Implement quality metrics and fail-closed capture diagnostics.
- [ ] Implement stabilization, regions/masks, segmentation, optical flow, consistency, filtering, and review.
- [ ] Integrate pinned local OpenCV.js through the bounded worker capability.

## Phase 7: Airflow model

- [ ] Implement model backend contract, zones, flow edges, evidence links, uncertainty, and maturity.
- [ ] Verify mass-balance inputs and editable assumptions.

## Phase 8: Simulation

- [ ] Implement deterministic compartment solver, scenarios, metrics, cache, cancellation, and replay.
- [ ] Implement accessible time-series and spatial run views.

## Phase 9: Optimization

- [ ] Implement scenario candidates, shared feasibility, deterministic search, Pareto ranking, and sensitivity.
- [ ] Verify known optima, alternatives, precision, and fragile-gain refusal.

## Phase 10: Recommendations

- [ ] Implement traceable recommendation contracts, structured explanations, and verification protocols.
- [ ] Implement typed local project queries and confirmed mutation previews.

## Phase 11: Verification loop

- [ ] Implement experiment snapshots, follow-up evidence, residuals, calibration proposals, and model history.
- [ ] Verify the complete before/after workflow.

## Phase 12: Accessibility polish

- [ ] Close keyboard, focus, reflow, forced-color, reduced-motion, touch, table, and live-status gaps.
- [ ] Complete automated and focused manual accessibility review.

## Phase 13: Full validation and hardening

- [ ] Close the requirement matrix with relevant automated evidence.
- [ ] Complete threat model, malformed-file, privacy, migration, worker, offline, and recovery tests.
- [ ] Complete dependency, secret, license, CSP/header, and network audit.

## Phase 14: Performance and observability

- [ ] Instrument privacy-safe product and scientific job diagnostics.
- [ ] Profile representative projects and fix measured bottlenecks.
- [ ] Enforce bundle/runtime budgets and low-capability fallbacks.

## Phase 15: Release audit

- [ ] Complete first-time-user and expert browser audits on desktop/mobile.
- [ ] Run clean-install release gates and inspect final worktree/history.
- [ ] Write final verification, limitations, supported-platform, and launch documentation.
- [ ] Deploy only if explicitly authorized; otherwise record local production-bundle proof.
